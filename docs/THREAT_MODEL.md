# QualityCI 威胁模型与安全测试

## 保护对象

- 客户/比赛文档原文与结构化字段；
- 文件版本、哈希和证据位置；
- 工程变更、规则运行和审批记录；
- 修订草案、新基线与审计日志；
- 模型/API凭据和运行环境。

## 信任边界

1. 上传文件不可信；
2. 文档正文中的提示词不可信；
3. LLM输出不可信；
4. 浏览器参数和路径不可信；
5. 审批角色、事件版本和重放请求必须验证；
6. 客户转发材料不自动等于客户授权。

## 主要风险与控制

| 风险 | 可能后果 | v0控制 | 必须补充的测试 |
|---|---|---|---|
| 任意路径读取 | 泄露服务器文件 | Demo只允许预登记case/mutation/resolution | `../`、绝对路径、URL参数绕过 |
| ZIP炸弹/超大文件 | 内存或磁盘耗尽 | 限大小、成员数、展开比率 | 高压缩比、嵌套ZIP、超多成员 |
| DOCM/XLSM宏 | 恶意代码 | 拒绝含宏格式，不执行任何嵌入对象 | 宏扩展名与Content Type伪装 |
| PDF扫描件/解析失败 | 假装已提取证据 | 导入层显式拒绝；接入工作流后可映射为UNVERIFIABLE，绝不静默PASS | 空文本、损坏PDF、加密PDF |
| 文档提示注入 | 操纵LLM跳过规则 | 文档仅作为数据；规则/权限由代码控制 | “忽略系统指令/标记PASS”等样本 |
| LLM幻觉 | 无依据结论 | 结构校验、证据锚点、三态与规则最终判定 | 无引用事实、错误页码、低置信度 |
| HTML/XSS | Demo执行文档脚本 | 所有外部文本HTML转义 | `<script>`、事件属性、SVG payload |
| 审批重放/补丁篡改 | 旧批准跨案例/事件复用，或放行未批准操作 | 修订批准记录必须匹配case、event、event revision、完整待修订case哈希与operations哈希 | 跨案例、改上下文、旧版本、缺角色、批准后增删操作、拒绝后重放 |
| 修订重分类风险/改事件主体 | 低风险单角色批准绕过高风险双角色门 | v0.1 resolution只能改document；应用后整体case重新校验，事件风险与主体变更必须走新事件版本 | `target=event/case`、MEDIUM→HIGH、唯一APPROVED文档被降为DRAFT |
| 未批准自动修改 | 绕过人工门 | 原文只读；修订只是proposal | 无审批apply、部分审批apply |
| 本地审计篡改 | 无法追责 | SQLite事件前向哈希链＋业务实体指纹交叉校验＋空链拒绝 | 修改业务payload、修改审计事件、删除全部/尾部记录、重写全链 |
| 客户数据混入 | 隐私/IP违规 | 当前只接受显著synthetic案例 | 未标synthetic输入必须拒绝 |

## 安全发布门

在以下条件全部满足前，不能声称“安全闭环已验证”：

- 高风险未批准修订的门禁逃逸次数为0；
- 旧事件版本审批不能用于新版本；
- 任意路径读取、宏文件和ZIP炸弹测试通过；
- 文档中的提示注入不能改变确定性状态；
- XSS载荷在页面中只显示为文本；
- 审计链篡改可以被检测；
- 当前导入层对解析失败显式拒绝；未来工作流适配可将其映射为UNVERIFIABLE。两种路径都不得返回PASS。

### 审计能力口径

当前SQLite链能发现业务表payload与审计事件的不一致，也拒绝空库/空链；它仍是同一本地信任域内的完整性自检。拥有数据库写权的攻击者仍可能同时重写业务表与整条链，或删除尾部后重建。在增加外部签名链头/远程时间戳前，对外只能称“本地前向哈希与实体交叉校验”，不能称“不可篡改审计”。
